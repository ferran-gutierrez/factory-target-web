- **REQ-1** The app exposes an **Export tasks** control; activating it downloads a JSON file whose parsed root is an array containing every task currently stored, with one object per task regardless of the active filter.
  `[@test] ../tests/taskImportExport.test.ts`

- **REQ-2** Each object in an export produced from tasks titled `Export me` (incomplete, normal priority, no due date) and `Done high` (completed, high priority, due date `2030-05-20`) includes at least `title`, `completed`, and `priority` with those values, includes `dueDate` only when the task has a due date, and includes a string `id` for each task.
  `[@test] ../tests/taskImportExport.test.ts`

- **REQ-3** The app exposes an **Import tasks** control that opens a file chooser restricted to JSON (for example `accept` including `.json` or `application/json`).
  `[@test] ../e2e/tasks.spec.ts`

- **REQ-4** Pure import validation accepts a JSON array of objects each having string `id`, string `title`, boolean `completed`, optional string `dueDate`, and optional priority `low`, `normal`, or `high`; objects without `priority` are treated as **normal** when converted to tasks.
  `[@test] ../tests/taskImportExport.test.ts`

- **REQ-5** Pure import validation rejects non-array JSON, arrays containing any object missing required fields or with wrong types, invalid `priority` values, or non-string `dueDate` when present.
  `[@test] ../tests/taskImportExport.test.ts`

- **REQ-6** When the user selects a valid import file and confirms the import confirmation prompt, the stored task list is replaced entirely by the imported tasks (for example existing title `Old task` disappears and titles from the file appear), and the new list is written to localStorage.
  `[@test] ../tests/taskImportExport.test.ts`

- **REQ-7** When the user selects a valid import file but dismisses the import confirmation prompt, the task list and localStorage contents remain unchanged.
  `[@test] ../tests/taskImportExport.test.ts`

- **REQ-8** When the user selects an invalid import file (for example `{ "not": "an array" }` or `[{ "title": "missing id" }]`), the app shows a clear, visible import error message and does not add, remove, or reorder tasks relative to the list before the import attempt.
  `[@test] ../tests/taskImportExport.test.ts`

- **REQ-9** After a successful import, a full page reload restores the same imported task titles, completion states, priorities, and due dates as immediately after import.
  `[@test] ../tests/taskPersistence.test.ts`

- **REQ-10** An end-to-end journey adds at least two tasks with distinct titles and mixed completion, priority, and due-date fields (for example one incomplete normal-priority task without a due date and one completed high-priority task with due date `2030-08-15`), exports tasks and captures the downloaded JSON, clears persisted tasks and reloads so the list is empty, imports the captured file via **Import tasks**, confirms the prompt, and verifies on screen each imported task's title, completion checkbox state, priority label (**Low**, **Normal**, or **High**), and due date accessibility label/value (including absence when no due date); then reloads the page and verifies the same title, completion, priority, and due-date assertions for every imported task.
  `[@test] ../e2e/tasks.spec.ts`

## Assumptions

- Export uses an in-browser download (for example `Blob` plus a temporary `<a download>`) with a `.json` filename; the file body is UTF-8 JSON representing the task array only (no wrapper object), matching the shape persisted in localStorage aside from omitted optional fields when unset.
- Import reads the chosen file with the File API, parses JSON once, runs the same validation rules as REQ-4 and REQ-5 before mutating the store, and uses a browser `confirm` dialog (or equivalent) for the replace-list step so Playwright can accept or dismiss it like delete confirmation.
- Replacing the list on import sets the in-memory store to the validated tasks in file order and overwrites the existing localStorage key; it does not merge with or append to prior tasks.
- Import error UI is a visible message in the app shell (for example an alert region or dedicated error text) that persists until the next import attempt or successful import, not only a console log.
- Valid import of an empty JSON array `[]` after confirmation yields an empty task list and empty persisted storage.
- Export with zero tasks still downloads a JSON file whose parsed content is an empty array.
- Invalid JSON syntax (parse failure) is treated as an invalid import file per REQ-8.
- Due dates in import files must be strings when present; validation does not require a specific date pattern beyond string type, and normalization matches existing persistence (optional field omitted when absent).
- Filters and sort mode are not included in export and are not reset by import beyond what a full list replace implies; filter still defaults to **all** on reload per earlier specs.
- No cloud upload, account sync, or automatic scheduled export—scope stays single-browser file pick and download within the bundle budget.
