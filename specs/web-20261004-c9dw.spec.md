description: Render a bottom-of-page footer showing factory attribution and the current calendar year, backed by a pure footer-text function with unit and E2E coverage.
targets:
  - src/**
  - index.html
  - tests/**
  - e2e/**

- **REQ-1** The app exports a pure function that accepts a numeric calendar year and returns exactly `Built by the LambdaLoopers factory` followed by one ASCII space and that year with no other characters.
  `[@test] ../tests/footerText.test.ts`

- **REQ-2** When the home page loads and `#app` is present, the document includes a `footer` element whose text content equals the pure function output for `new Date().getFullYear()` at render time.
  `[@test] ../e2e/footer.spec.ts`

- **REQ-3** On the home page, the footer is visible and its bottom edge aligns with the bottom of the viewport within a 2px tolerance when the viewport is at least 600px tall.
  `[@test] ../e2e/footer.spec.ts`

- **REQ-4** Application mount logic invoked with a null root container completes without throwing and creates no `footer` element in the supplied container tree.
  `[@test] ../tests/mount.test.ts`

## Assumptions

- Footer copy uses the fixed phrase `Built by the LambdaLoopers factory` and appends the year after a single space (for example `Built by the LambdaLoopers factory 2026`).
- The pure function lives in a dedicated module under `src/` (for example `src/footerText.ts`) and takes the year as an argument so unit tests do not depend on the system clock.
- The UI obtains the current year via `new Date().getFullYear()` when mounting the footer; only the pure function is exercised with fixed years in unit tests.
- The existing heading behaviour in `src/main.ts` remains unchanged; the footer is added alongside it when `#app` exists.
- Bottom placement is achieved with conventional CSS layout (for example flex column on `body` with the main content growing and the footer following it) without introducing external assets or runtime network calls.
- Mount logic is factored so `../tests/mount.test.ts` can call it with a minimal in-memory DOM stub in Node without changing Vitest environment settings.
