## Assumptions

- Task identity uses stable generated ids (for example UUID) so edits, completion toggles, and deletes target the correct row after reload.
- New tasks are appended in creation order unless the UI explicitly reorders; tests assert by title and completion, not display order, except where order is implied by the E2E steps.
- Title validation trims leading and trailing whitespace; a title of only whitespace is treated as empty per REQ-2.
- Delete confirmation uses the browser `confirm` dialog (or an equivalent single confirm/cancel prompt) so Playwright can accept or dismiss it in E2E.
- Filter selection resets to **all** on full page reload; only tasks and their fields persist, not the active filter tab or search query.
- localStorage uses one fixed application-specific key holding a JSON array of task objects with string `id`, string `title`, boolean `completed`, optional ISO `YYYY-MM-DD` `dueDate`, and `priority` `low`|`normal`|`high` (missing `priority` normalizes to normal); missing storage or a completely unreadable stored value (parse failure or non-array root) yields an empty list with no skip notice; a parseable array with invalid entries loads valid tasks only, shows a skip-count notice, and persists the valid subset.
- Editing uses an explicit edit/save flow in the UI (inline or small form) rather than contenteditable without save, so E2E can target stable roles or labels.
- The existing smoke E2E heading may be replaced or incorporated into the task app shell; bundle size stays within the 60 KB gzip JS budget per AGENTS.md.
- No backend, accounts, or sync—scope is single-browser localStorage only; due dates and priorities are in scope via later specs.
