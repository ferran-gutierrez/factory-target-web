- **REQ-1** The app exposes a search control directly above the task list with accessible name **Search tasks** so users and tests can locate it without relying on list markup alone.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-2** Pure title-search logic returns only tasks whose title contains the query as a case-insensitive substring (for example query `apple` matches **Buy Apples** but not **Banana run**).
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-3** Visible tasks are the intersection of the active completion filter (all, active, or done) and the current search query: with filter **active**, stored tasks **Milk active** (incomplete) and **Milk done** (complete), and search query `milk`, only **Milk active** is included.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-4** When at least one task is stored but the combined completion filter and search query match zero tasks, the app shows visible text **No tasks match** and does not render task list rows for that state.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-5** When there are no stored tasks, the app shows the empty-list message (for example copy matching **No tasks yet — add a task to get started.**) and does not show **No tasks match**, even if the search box contains text.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-6** Clearing the search box (empty query) restores the task list to whatever titles the active completion filter alone would show, without changing stored tasks or the active filter.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-7** Search text is held only in memory for the current page session; after a full page reload the search box is empty and every stored task visible under the default **all** filter appears in the list.
  `[@test] ../e2e/tasks.spec.ts`

- **REQ-8** Sort mode applies after completion filter and search (for example with **all** filter, search `z`, and tasks **Alpha z** and **Beta z** added in that order, **Creation order** sort lists **Alpha z** before **Beta z**).
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-9** An end-to-end journey adds tasks **Cherry pie** and **Apple tart**, types `apple` into **Search tasks** and verifies only **Apple tart** appears, switches to **Active** after marking **Apple tart** complete and verifies **No tasks match** is shown, clears the search box and verifies **Cherry pie** appears under **Active**, reloads the page and verifies the search box is empty and both tasks are visible under **All**.
  `[@test] ../e2e/tasks.spec.ts`

## Assumptions

- The search control is a text `<input>` (or equivalent) placed in the app shell immediately above the task list `<ul>`, below the existing filter and sort controls.
- Title search trims leading and trailing whitespace on the query; an all-whitespace query behaves like an empty query (no title filtering beyond the completion filter).
- Completion filter still defaults to **all** on reload per earlier specs; only task records persist in localStorage, not search text, filter tab, or sort mode.
- **No tasks match** is exact user-visible copy (including capitalization) distinct from the empty-list message defined in `web-20261004-jrtx.spec.md` REQ-11.
- Pure search helpers live alongside existing filter helpers (for example in `src/taskFilters.ts`) so unit tests can compose completion filter and search without mounting the DOM except where UI placement is required.
- Search does not affect export/import payloads, skip notices, or stored task shape; it only affects which rows render.
