- **REQ-1** When the app loads, the main view renders one root SVG element that displays a world map using inline `path` elements for country geometry.
  `[@test] ../tests/world-map.test.ts`
  `[@test] ../e2e/world-map.spec.ts`

- **REQ-2** The number of country features rendered matches the Natural Earth 1:10m Admin 0 countries dataset (every included sovereign country and dependency in that layer is present; none omitted).
  `[@test] ../tests/world-map.test.ts`

- **REQ-3** Each country path’s `d` attribute preserves the original Natural Earth 1:10m coordinate sequences without simplification, quantization, vertex dropping, or geometry loaded from runtime network or separate static file fetches.
  `[@test] ../tests/world-map.test.ts`

- **REQ-4** All country border path data and country name metadata ship inside the JavaScript application bundle via static TypeScript/JavaScript imports (no `fetch`, `XMLHttpRequest`, or dynamic import of external URLs for map data at runtime).
  `[@test] ../tests/world-map.test.ts`
  `[@test] ../e2e/world-map.spec.ts`

- **REQ-5** The embedded path-data source used by the bundle contains at least 2,097,152 bytes (2 MiB) of path `d` string content before gzip compression or production build minification, and a unit test fails if that size is below the threshold.
  `[@test] ../tests/world-map-data-size.test.ts`

- **REQ-6** When the pointer hovers over a country path, the UI shows that country’s English name in a visible, human-readable label associated with the map (for example a dedicated name element updated on hover).
  `[@test] ../e2e/world-map.spec.ts`

- **REQ-7** When the pointer hovers over a country path, that country’s path(s) receive a highlighted visual state distinct from non-hovered countries until the pointer leaves the country.
  `[@test] ../e2e/world-map.spec.ts`

- **REQ-8** An end-to-end journey opens the home page, hovers France, Egypt, and Australia in sequence, and asserts the displayed name matches `France`, `Egypt`, and `Australia` respectively.
  `[@test] ../e2e/world-map.spec.ts`

- **REQ-9** During the end-to-end map journey, the page does not issue network requests for map geometry or country lists (document navigation to the app origin only).
  `[@test] ../e2e/world-map.spec.ts`

## Assumptions

- The feature request takes precedence over the repository’s 60 KB gzip JavaScript bundle budget: embedding full Natural Earth 1:10m path data (≥ 2 MiB raw) cannot satisfy `npm run check:size` under current `scripts/check-size.mjs`; satisfying REQ-3 through REQ-5 is in scope for implementation on allowed paths, and raising or exempting the bundle budget requires a separate change to protected check definitions (out of scope for allowed paths).
- Country display names use Natural Earth Admin 0 attributes, preferring `NAME_EN` when present and otherwise `NAME`, matching the strings asserted in REQ-8.
- Natural Earth 1:10m `ne_10m_admin_0_countries` (or equivalent Admin 0 countries layer at 1:10m) is the authoritative geometry and country list source; dependencies and Antarctica are included as that layer defines them.
- A country may consist of multiple SVG `path` elements (e.g. MultiPolygon); hover name and highlight apply to the whole country via shared identifiers or grouping so REQ-6 and REQ-7 behave consistently.
- The placeholder heading-only home page is replaced by the map as the primary `#app` content; the map remains usable without persistence or user settings.
- E2E hover targets use stable `data-country-code` (ISO 3166-1 alpha-3) or role-based selectors on paths so France, Egypt, and Australia can be hovered without relying on pixel-perfect coordinates alone.
