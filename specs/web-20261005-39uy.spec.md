- **REQ-1** The app exposes a search control above the task list with accessible name **Search tasks**; typing in it filters which task rows are visible without removing tasks from storage.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-2** Title search is a case-insensitive substring match on each task's stored title (for example query `buy` matches **Buy milk** and **Rebuy stamps** but not **Milk only**).
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-3** Search combines with the completion filter: with filter **active**, query `work` shows only incomplete tasks whose titles contain `work` (for example after adding **Homework** incomplete and **Workout** completed, **active** plus `work` lists only **Homework**); with filter **done**, the same query lists only completed matching titles.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-4** Pure search helpers apply case-insensitive substring filtering on titles without requiring the DOM.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-5** Pure helpers (or the same pipeline the UI uses) apply completion filter first then search so the visible set matches REQ-3.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-6** When at least one task is stored but the combined completion filter and search yield zero visible tasks, the app shows visible message **No tasks match**, hides the task list, and does not show the zero-stored-tasks empty state from `web-20261004-jrtx.spec.md` REQ-11.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-7** Clearing the search input (empty or whitespace-only query) restores the list to all tasks that match the current completion filter only, with sort unchanged.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-8** Search text is held only in memory for the session; after a full page reload the search control is empty and every stored task visible under filter **all** appears regardless of what was typed before reload.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-9** An end-to-end journey adds tasks **Garden weeds** and **Pay bills** (incomplete), marks **Pay bills** complete, sets filter **active**, types `garden` into **Search tasks** and sees **Garden weeds** while **Pay bills** is hidden, clears search and still sees only **Garden weeds** under **active**, switches to **all** and sees both titles, types `xyz` and sees **No tasks match** with no list rows, clears search to restore both titles, reloads the page, and verifies the search box is empty and both titles are visible under **all**.
  `[@test] ../e2e/tasks.spec.ts`

## Assumptions

- The search control is a text `<input>` placed above the task list (below the add form and completion filter bar), with `aria-label` or an associated label **Search tasks**, matching the **Task title** label pattern.
- Whitespace-only search is treated as no search (same visibility as an empty query).
- **No tasks match** is shown exactly with that capitalization and punctuation; the zero-stored-tasks message remains **No tasks yet — add a task to get started.** per updated `web-20261004-jrtx.spec.md` REQ-11.
- Sort mode (**Creation order**, **Due date**, **Priority**) still applies to the visible subset after completion filter and search; sort and completion filter defaults on reload stay as in earlier specs.
- Search does not affect export (export still includes every stored task) or import validation; import replace behaviour is unchanged.
- Supersedes web-20261004-jrtx REQ-11: When the current filter shows zero tasks, the app displays an empty state that tells the user to add a task (for example when the list is empty or when no tasks match the filter). becomes When there are zero stored tasks, the app displays an empty state that tells the user to add a task (for example **No tasks yet — add a task to get started.**); when stored tasks exist but none match the current completion filter and search query, the app shows **No tasks match** instead of the list.
- Supersedes web-20261004-jrtx assumption: Filter selection resets to **all** on full page reload; only tasks and their completion state persist, not the active filter tab. becomes Filter selection resets to **all** on full page reload; the search box is empty after reload; only tasks and their fields persist, not the active filter tab or search text.
- Supersedes web-20261004-cbd7 assumption: Filters (all / active / done) continue to work as today; sort applies to the filtered subset in display order. becomes Filters (all / active / done) and optional title search combine (completion filter first, then case-insensitive title substring); sort applies to that visible subset in display order.
- Supersedes web-20261005-dyyq assumption: Priority sort applies to the current filtered subset, consistent with creation-order and due-date sort; sort mode still defaults to **Creation order** on full page reload and is not persisted in localStorage. becomes Priority sort applies to the current visible subset after completion filter and search, consistent with creation-order and due-date sort; sort mode still defaults to **Creation order** on full page reload and is not persisted in localStorage.
- Supersedes web-20261005-4s3i assumption: Filters and sort mode are not included in export and are not reset by import beyond what a full list replace implies; filter still defaults to **all** on reload per earlier specs. becomes Filters, search text, and sort mode are not included in export and are not reset by import beyond what a full list replace implies; filter still defaults to **all** and search defaults to empty on reload per earlier specs.
- Supersedes web-20261004-cbd7 assumption: Overdue UI applies only to incomplete tasks visible under the current filter; completed tasks skip overdue styling even if past due. becomes Overdue UI applies only to incomplete tasks visible under the current completion filter and search; completed tasks skip overdue styling even if past due.
- Supersedes web-20261004-cbd7 assumption: Sort mode defaults to **Creation order** on full page reload (same as filter not persisting); only tasks and their fields persist in localStorage. becomes Sort mode defaults to **Creation order** on full page reload (same as filter and search not persisting); only tasks and their fields persist in localStorage.
