- **REQ-1** The app exposes a search control with accessible name **Search tasks** placed above the task list; typing updates the visible list without submitting a form.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-2** Pure search helpers keep a task visible when its title contains the query as a case-insensitive substring (for example query `MILK` matches title `Buy milk` and query `buy` matches `Buy milk` but not `Walk dog`).
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-3** Title search combines with the completion filter: with filter **active** and query `alpha`, an incomplete task titled `Alpha chore` is visible and a completed task titled `Alpha done` is hidden; with filter **done** and the same query, only the completed task is visible.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-4** When the trimmed search query is non-empty, at least one task is stored, and no stored task matches the query under the current completion filter, the app shows visible copy **No tasks match** and does not render task list rows.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-5** When there are zero stored tasks and the search box is empty, the app shows the add-task empty-state message (for example `No tasks yet — add a task to get started.`) and not **No tasks match**.
  `[@test] ../tests/taskFilters.test.ts`

- **REQ-6** Clearing the search input (empty or whitespace-only after trim) restores the task list to whatever titles the current completion filter and sort mode would show with no search query.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-7** After a full page reload, the search input value is empty; previously entered search text is not read from or written to localStorage.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-8** An end-to-end journey adds tasks titled `Cherry task`, `Banana task`, and `Apple task`, types `apple` into **Search tasks** and verifies only **Apple task** appears, clears the search and verifies all three titles appear, types `zzznomatch` and verifies **No tasks match** is shown, switches to **Active**, marks **Banana task** complete, types `task` and verifies **Cherry task** and **Apple task** appear while **Banana task** is hidden, then reloads the page and verifies the search box is empty and all three titles are visible under **All**.
  `[@test] ../e2e/taskSearch.spec.ts`

## Assumptions

- Search queries trim leading and trailing whitespace; an empty string after trim applies no title filter (same as a cleared box).
- The no-match message text is exactly **No tasks match** (capital N, rest lowercase except proper nouns none).
- Search applies to stored task titles only (not priority labels, due dates, or ids); completion filter runs first, then title search, then sort mode on the remaining tasks.
- The search control is a text `<input>` (or equivalent) with `aria-label` or associated label **Search tasks**, placed in the DOM immediately above the task list element.
