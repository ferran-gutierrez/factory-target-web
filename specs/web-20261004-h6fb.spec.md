## Assumptions

- Core list, filter, and persistence behavior lives in testable TypeScript modules under `src/`; the UI in `src/` calls those modules.
- Each task has a stable internal id, a string title, and a boolean completed flag; ids are unique among tasks in the list.
- New task titles are trimmed; titles that are empty after trimming are rejected (REQ-3).
- The default selected filter on first visit is All.
- Delete confirmation uses the browser’s native confirm dialog (`window.confirm`); declining leaves the task list and storage unchanged.
- Editing is done in the UI per task (for example an editable field or an explicit edit action); the spec only requires that the saved title updates in the list (REQ-4).
- Empty state (REQ-9) applies whenever the active filter shows zero tasks, including when all tasks are hidden by Active or Done filters.
- Persistence uses a single fixed `localStorage` key dedicated to this app; serialized JSON includes enough data to restore ids, titles, and completion flags.
- E2E tests run against the Vite dev/preview server configured in the repo and accept Playwright’s dialog handler for confirm/cancel on delete.
