## Assumptions

- Task list logic lives in testable TypeScript modules under `src/`; the UI in `src/` and `index.html` wires those modules to the DOM.
- New tasks are added via the new-task field plus either an Add button or Enter in that field; both paths behave the same.
- Title edits use per-task inline editing started by an explicit Edit control and committed by Save or Enter, or cancelled by Escape without changing the title.
- Delete confirmation uses the browser `window.confirm` dialog; E2E tests accept or dismiss via Playwright's dialog handler.
- The default filter on first visit is All.
- Invalid or missing `localStorage` data is treated as an empty task list without breaking the app.
- Empty-state copy is implementation-defined as long as it mentions adding a task or adjusting the filter, and E2E asserts presence of that region rather than exact marketing copy.
- Each task has a stable internal id separate from its title so edits and toggles target the correct row.
