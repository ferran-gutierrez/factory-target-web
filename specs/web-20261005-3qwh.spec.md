- **REQ-1** The app exposes a search control immediately above the task list (`ul`) with a visible accessible name **Search tasks** so users and tests can locate the field without relying on unlabeled inputs alone.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-2** While the user types in **Search tasks**, visible list rows are limited to tasks whose titles contain the current query as a case-insensitive substring, after applying the active completion filter (all, active, or done); for example with stored tasks titled `Plan Alpha` (incomplete), `plan beta` (incomplete), and `Ship Gamma` (complete), filter **Active** selected, and query `PLAN`, only `Plan Alpha` and `plan beta` appear and `Ship Gamma` stays hidden.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-3** Pure title-search helpers (for example under `src/taskFilters.ts` or a sibling module) apply case-insensitive substring matching to a task array without requiring the DOM, so unit tests can assert match and non-match titles directly.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-4** When at least one task is stored, the trimmed search query is non-empty, and no stored task matches the combined completion filter and title search, the app hides the task list and shows visible copy **No tasks match** instead of the add-a-task empty state.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-5** When there are zero stored tasks, the app shows the existing add-a-task empty state (for example **No tasks yet — add a task to get started.**) and does not show **No tasks match**, even if the search box contains text.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-6** Clearing the search box (empty value or whitespace-only query) restores list rows for the current completion filter and sort without requiring a page reload.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-7** Search text is not written to localStorage; after a full page reload the **Search tasks** field is empty and every stored task is visible under the default **All** filter regardless of what was typed before reload.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-8** The selected sort mode (**Creation order**, **Due date**, or **Priority**) still orders the tasks that remain visible after completion filter and title search (for example priority sort orders only search-matched rows).
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-9** An end-to-end journey adds tasks titled `Searchable One` and `Other task`, types a query that matches only `Searchable One` and verifies that row alone is visible, types a query that matches neither title and verifies **No tasks match** is shown with no list rows, clears the search and verifies both titles return, switches to **Done** after completing one task and verifies search combined with **Done** hides non-matching completed titles, then reloads and verifies the search box is empty and tasks are visible again under **All**.
  `[@test] ../e2e/tasks.spec.ts`

## Assumptions

- Search matches task `title` only (not priority labels, due dates, or ids); trimming leading and trailing whitespace defines the effective query, and a whitespace-only query is treated as empty (same as cleared search).
- **No tasks match** is exact visible copy (no trailing punctuation required); the add-a-task empty state remains the existing `EMPTY_STATE_MESSAGE` from filter behaviour when the search box is empty per `web-20261004-jrtx` REQ-11.
- The search control is a text `<input>` (or equivalent) placed in the app shell directly above the task list, below the add-task form and existing filter/sort/import controls unless layout requires only the list adjacency constraint from REQ-1.
- Search applies after `filterTasks` and before sort helpers in the render pipeline; export/import and stored task arrays remain unaffected by the current search query.
- Supersedes web-20261004-jrtx REQ-11: When the current filter shows zero tasks, the app displays an empty state that tells the user to add a task (for example when the list is empty or when no tasks match the filter). becomes When the search box is empty and no tasks are visible because there are zero stored tasks or because the current completion filter (all, active, or done) hides every stored task, the app displays an empty state that tells the user to add a task (for example **No tasks yet — add a task to get started.**).
- Supersedes web-20261004-jrtx assumption: Filter selection resets to **all** on full page reload; only tasks and their completion state persist, not the active filter tab. becomes Filter selection resets to **all** on full page reload; only tasks and their fields persist in localStorage, not the active filter tab, search text, or sort mode.
- Supersedes web-20261004-cbd7 assumption: Filters (all / active / done) continue to work as today; sort applies to the filtered subset in display order. becomes Completion filters (all / active / done) and optional title search combine before sort; sort applies to the visible subset after both filter and search.
- Supersedes web-20261005-dyyq assumption: Priority sort applies to the current filtered subset, consistent with creation-order and due-date sort; sort mode still defaults to **Creation order** on full page reload and is not persisted in localStorage. becomes Priority sort applies to tasks visible after the completion filter and title search, consistent with creation-order and due-date sort; sort mode still defaults to **Creation order** on full page reload and is not persisted in localStorage.
