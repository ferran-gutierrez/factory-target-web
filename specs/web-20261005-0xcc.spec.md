- **REQ-1** The app exposes a search control with accessible name **Search tasks** placed directly above the task list (`<ul>`); typing in the control filters which task rows appear without removing tasks from storage.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-2** Pure search helpers keep a task visible when its title contains the query as a case-insensitive substring (for example query `buy` matches **Buy milk** and **ReBUY soon**); tasks whose titles do not contain the query are excluded.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-3** Title search combines with the all/active/done filter: with filter **Active**, query `beta` shows only incomplete tasks whose titles match (for example **Beta task** but not completed **Beta done**); with filter **Done**, the same query shows only completed matching tasks.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-4** When the trimmed search query is non-empty, at least one stored task matches the current all/active/done filter, and no task matches both filter and search, the app shows visible text **No tasks match**, hides the task list, and does not show the add-task empty state from `web-20261004-jrtx` REQ-11.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-5** When the stored task list is empty, the app shows the add-task empty state per `web-20261004-jrtx` REQ-11 and does not show **No tasks match**, even if the search box contains text.
  `[@test] ../tests/taskFilters.test.ts`

- **REQ-6** Clearing the search input (empty or whitespace-only query) restores the task list to whatever tasks match the current filter and sort without requiring a page reload.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-7** After a full page reload, the search control is empty and every stored task matching the default **All** filter is visible regardless of what was typed before reload.
  `[@test] ../tests/taskSearch.test.ts`

- **REQ-8** An end-to-end journey adds tasks **Apple pie**, **Banana bread**, and **Apricot jam**, searches for `ap` and verifies **Apple pie** and **Apricot jam** appear while **Banana bread** is hidden, switches to **Active** after marking **Apricot jam** complete and verifies search still hides non-matching active titles, enters a query that matches no filtered task (for example `zzzz`) and verifies **No tasks match** with no list rows, clears search and verifies all tasks matching the current filter return, then reloads and verifies the search box is empty and the full list is visible again.
  `[@test] ../e2e/tasks.spec.ts`

## Assumptions

- Supersedes web-20261004-jrtx REQ-11: When the current filter shows zero tasks, the app displays an empty state that tells the user to add a task (for example when the list is empty or when no tasks match the filter). becomes When there are no stored tasks, or when the active all/active/done filter leaves zero tasks while the search box is empty, the app displays an empty state that tells the user to add a task.
- Supersedes web-20261004-jrtx assumption: Filter selection resets to **all** on full page reload; only tasks and their completion state persist, not the active filter tab. becomes Filter selection resets to **all** on full page reload; only tasks and their fields persist, not the active filter tab or search query.
- Supersedes web-20261004-cbd7 assumption: Filters (all / active / done) continue to work as today; sort applies to the filtered subset in display order. becomes Status filters (all / active / done) and title search combine as today: search restricts the filter-visible tasks; sort applies to that visible subset in display order. Search text is not persisted on reload.
- Supersedes web-20261005-dyyq assumption: Priority sort applies to the current filtered subset, consistent with creation-order and due-date sort; sort mode still defaults to **Creation order** on full page reload and is not persisted in localStorage. becomes Priority sort applies to the current status-filtered and search-filtered visible subset, consistent with creation-order and due-date sort; sort mode still defaults to **Creation order** on full page reload and is not persisted in localStorage. Search query is also not persisted on reload.
- The no-match message text is exactly **No tasks match** (testable via visible text or a dedicated status element).
- Search matching trims leading and trailing whitespace on the query; an empty query after trim applies no title restriction (same visible set as filter-only).
- Search runs on stored task titles after the all/active/done filter and before sort; changing filter, sort, or search re-renders the list in one pass.
- The search control is a text input (not persisted in localStorage or export JSON); only task records persist per earlier specs.
- When the all/active/done filter leaves zero tasks and the search box is empty, REQ-11 empty state still applies; **No tasks match** applies only when the filter subset is non-empty but the trimmed search excludes every member of that subset.
- Existing edit, delete, import/export, due-date, priority, and overdue behaviour stays unchanged aside from which rows are visible under search.
