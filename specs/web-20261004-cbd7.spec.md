## Assumptions

- Due dates are calendar dates only (no time-of-day); “today” and comparisons use the browser’s local timezone.
- Stored due dates use an ISO `YYYY-MM-DD` string on each task; omitted or cleared means no due date. Existing saved tasks without a `dueDate` field load as having no due date.
- The add and edit flows use an HTML `date` input (or equivalent) for picking due dates; E2E sets values in `YYYY-MM-DD` form.
- Overdue UI applies only to incomplete tasks visible under the current filter; completed tasks skip overdue styling even if past due.
- Sort mode defaults to **Creation order** on full page reload (same as filter not persisting); only tasks and their fields persist in localStorage.
- When both sort modes are shown, **Creation order** is the initial selection on first visit.
- Display of due dates in the list is human-readable but testable via role or label (for example `Due date` plus the shown value); overdue rows expose a testable `Overdue` indicator.
- Date logic lives in dedicated pure functions (for example under `src/taskDates.ts`) so unit tests can inject a fixed reference day without mocking the system clock in every test.
- Status filters (all / active / done) and title search combine as today: search restricts the filter-visible tasks; sort applies to that visible subset in display order. Search text is not persisted on reload.
- No reminders, recurring due dates, time zones per user, or server sync—scope stays single-browser localStorage within the existing bundle budget.
